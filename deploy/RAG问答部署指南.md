# RAG 问答部署指南（本地大模型接入）

> 瀚钦OPC财税智能体管理平台 (c) 2026 瀚钦科技有限公司. All rights reserved.
> 适用版本：平台 v0.5.0+（BM25 检索层已内置并测试通过）

## 一、当前形态（v0.5.0 出厂即用）

- **检索**：纯 Python 中文双字 BM25（`opc_fin_agent/kb.py`），无第三方依赖，**无需部署即可真检索**；
- **回答**：`extractive` 抽取式——直接引用命中条款原文（结论/依据/适用条件/来源四要素），比生成式更诚实；
- **知识库**：`config/kb_docs/*.json`，每份带来源/发布日期/版本/审签人。**未审签（reviewed_by 为空或 status≠approved）不进检索，这是硬编码门禁**；
- **拒答**：检索分 < 阈值（`min_score`，默认 3.5）或命中词条 < 2 → "证据不足，请提交人工复核"；
- **C级守门**：优惠/筹划/免税/入账处理类问题一律不给结论，附参考来源转专业人员。

## 二、接入 Ollama 本地大模型（部署服务器）

```bash
# 1. 安装 Ollama（Linux，官方脚本；离线环境用 tar 包）
curl -fsSL https://ollama.com/install.sh | sh

# 2. 拉取模型（7B 级即可满足问答；首次需联网，之后完全离线）
ollama pull qwen2.5:7b

# 3. 改配置 config/kb_config.json
"answer_mode": "extractive"  ->  "answer_mode": "llm"
#   llm.base_url 默认 http://127.0.0.1:11434，model 默认 qwen2.5:7b

# 4. 重启服务即生效；知识库更新无需重启（按文件指纹自动重建索引）
```

**模型宕机/超时/回答不含出处编号时，系统自动回退抽取式回答并置 `mode=extractive-fallback`**——大模型说得好不如条款引得准，这条回退是产品纪律，不是降级容错。

## 三、验收标准

| 项 | 标准 |
|---|---|
| 带出处回答 | 每条 answered=true 的回答必含 source/date/version/segment_id |
| 拒答 | 无关问题、弱匹配问题必须回答"证据不足"，严禁自由发挥 |
| C级守门 | "能不能享受优惠"类问题必须转人工，不得给出结论 |
| 审签门禁 | reviewed_by 为空的文档不得出现在 /api/v1/kb/documents 的 indexed 列表 |
| llm模式 | 回答末尾必须有出处编号；模型进程被 kill 后 30s 内回退 extractive |
| 回归 | 5 套测试全绿（tests/kb_test.py 含 LLM 回退用例） |

## 四、知识库运营纪律（长期）

1. **只喂一手来源**：法规从税务总局/财政部官网取原文，企业制度须财务负责人签字；
2. **演示条目替换**：上线前把 `config/kb_docs/` 全部演示占位条目（来源含"演示占位"字样）替换为真实条目并补审签人；
3. **月度更新**：政策变化（税率、征期顺延、优惠到期）当月入库，旧版本保留 `version` 递增；
4. **容量参考**：BM25 检索在数千段落内性能无压力；上万段落后再评估接入本地向量模型（bge-small 适配位已在检索层预留：`BM25Index` 换实现即可，接口不变）。

## 五、安全注意

- Ollama 仅监听内网（默认 127.0.0.1），**禁止**绑定 0.0.0.0 或反代到公网；
- 提示词强制"只允许使用资料内容"，模型输出不直接对外，仅供问答层组装——C级守门在模型之前生效，任何模式都绕不过。
